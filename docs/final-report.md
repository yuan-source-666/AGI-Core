## 摘要

AGI-Core 是一个在本地 CPU 环境下从零构建的多模态认知智能原型系统，完成了「顶层架构 → 核心算法 → 数据管道 → 多模态模块 → 系统集成」的完整研发闭环。系统采用感知 / 认知 / 决策 / 输出四层解耦架构，层间通过统一的 JSON 信封契约（I1–I6）通信，全部实现基于 Python 标准库，零外部依赖、零预训练权重、零外网调用。

**验收结论：GOAL.md 六条验收标准全部达成（6/6）。** 实测集成演示 21/21 通过、3 个演示场景全通，认知核心自测 11/11、多模态自测 19/19、数据管道 12/12 硬断言通过；数据集有效样本 240 条（要求 ≥200）；端到端单轮平均延迟 62.8ms（预算 <5000ms），为预算的 1.3%。

需要明确指出的是：本系统的全部量化指标均在**封闭词表（30 概念槽 × 12 句式模板）的合成数据**上取得，衡量的是契约一致性、管道正确性与系统自洽性，**不代表开放域语义理解能力**。本报告 §6 对此作了不加修饰的陈述。

`tests/acceptance.py` 是 Phase 5 的全量测试统一入口，对照 GOAL 六条逐条自动核销：

设计要点：**独立判定**（每条自带客观判据，子测试经 subprocess 隔离调用并解析实际输出，不采信模块自我声明）、**永不阻塞**（单项超时或崩溃记为 FAIL 并继续，不中断其余验收项）、**退出码门禁**（0 = 六条全过，1 = 存在未通过项，可直接接入 CI）。

**环境无关性（v1.0 交付后修复的缺陷）**：验收首版未固定子进程 I/O 编码，在中文 Windows 上出现「父进程 stdout 为 UTF-8、子进程管道却为 GBK」的分裂——子进程打印 `✅` 即抛 `UnicodeEncodeError` 崩溃，验收 4、5 误判为 FAIL。修复分两层：其一，验收脚本为子进程注入 `PYTHONIOENCODING=utf-8` 并以 UTF-8 解码其输出，**父子两侧同时钉死**，使结论不再随终端漂移；其二，删除 4 个交付脚本 `print` 路径上的 GBK 不可编码字符（✅❌⑪⑫ 替换为 `[OK]` `[FAIL]` `11.` `12.`），使项目在默认 GBK 控制台下亦可直接运行。修复后已在 GBK 与 UTF-8 两种环境下各跑一次，均得 6/6、退出码 0。

> 注：`data/build_dataset.py` 中另有 5 处 ✅/❌ 被保留——它们写入 `data/quality_report.md`（显式 `encoding="utf-8"`），不经过 stdout，无编码风险；保留是为让 Markdown 报告保持可读的视觉标记。

## 3. 关键技术实现

### 3.1 四层架构落地

```
感知层  perceive(inputs) → Observation[]        64 维共享空间嵌入，三模态容错编码
   ↓ I1
认知层  run_cognition(obs, query, sid) → Thought  记忆检索 → 注意力加权 → 三通道推理
   ↓ I2
决策层  plan(thought) → Action                  置信度门控 0.6：reply / clarify
   ↓ I4
输出层  render(action, ctx) → Response          text + confidence + trace + latency_ms
```

全链路唯一入口 `dispatch(request) -> response`，永不抛异常，错误按 `1xxx 感知 / 2xxx 认知 / 3xxx 数据 / 4xxx 集成` 四段错误码在信封内传播。

### 3.2 认知核心（M1）

- **注意力**：零参数打分，四因子加权 α·余弦 + β·IDF-Jaccard + γ·新鲜度 + δ·显著性（0.45/0.30/0.15/0.10），Top-K(8) 截断 + softmax(T=0.5)。以可解释打分替代 QK 投影，规避 GPU 依赖（对齐降级预案 R1）。
- **记忆**：工作记忆（内存 deque）/ 情景记忆（JSONL）/ 语义记忆（JSONL）三层。遗忘曲线衰减（低于 0.2 归档而非删除）、巩固机制（hits≥3 或簇余弦 >0.75 且 ≥5 条 → 蒸馏为语义记忆）、写入时相似合并（cos≥0.95）。
- **推理**：规则前向链接（11 条种子规则，链深 ≤3）+ 记忆证据投票 + 模板兜底，三通道加权仲裁（0.5/0.35/0.15）；置信度 <0.6 转 `clarify` 追问而非强行作答。
- **认知循环**：工作记忆写入 → 推理 → 情景回写 → 巩固与衰减，实现「对话即学习」闭环。

### 3.3 多模态（M2）

- **64 维结构化共享空间**：A[0,48) 概念锚区 / B[48,56) 意图区 / C[56,64) 私有区。同一概念名在三模态经带符号双槽 md5 哈希落入**相同槽位**，使跨模态对齐成为结构性质而非学习结果。
- **三模态编码**：文本走概念词典最大匹配 + IDF 词袋；图像走原型 top-2 概念软匹配 + 私有区投影；语音走语气原型匹配 + 意图/语气锚。
- **三级对齐**：T0 内置概念表（兜底）→ T1 原型统计（默认，落盘 `prototypes.json`）→ T2 纯 Python 岭回归闭式校准（仅当检索 top-1 <70% 时启用，实测未触发）。

### 3.4 数据管道（M3）

合成生成 300 条 → 主动注入 20% 四类噪声（重复 8% / 近重复 4% / 格式 4% / 异常 4%）→ 五步清洗（校验 / 精确+近似去重 / 异常剔除 / 归一化 / 质量打分）→ 分层划分。seed=42 确定性可复现，同 seed 二次构建逐字节一致。

### 3.5 系统集成（M4）

- 路由表 + 懒导入 + 双层桩降级（模块桩 → M4 内置兜底桩），单模块缺席不阻塞整体演示（对齐 R4）。
- **共享语义空间桥接**：M4 懒取 M2 的 `embed_text(query)`，包装为 `meta.role="query"` 的观测注入 M1。此设计在不违反「M1/M2 禁止互相 import」边界的前提下，让认知层的注意力 α 通道使用真实语义嵌入。
- **会话状态持久化**：`data/session_state.jsonl` 追加式存储，读写失败降级为内存态。

## 6. 局限性与诚实评估

以下为客观陈述，不作修饰。它们不是缺陷清单，而是界定这套原型系统能力边界的坐标。

**L1 · 封闭世界假设（最根本的局限）。** 全部数据来自 30 个概念槽 × 12 个句式模板的合成生成，词汇表封闭。所有 1.000 的指标衡量的是「封闭词表内的系统自洽性」，系统对词表外的任何输入没有泛化能力。这不是 bug，是设计边界——但必须说清楚：它不等于语义理解。

**L2 · 零学习参数。** 注意力是手工设计的打分函数而非学习到的权重；跨模态对齐靠概念名哈希同槽 + 掩码余弦，而非训练得到的映射；对齐的 T2 岭回归一路径虽已实现但从未被触发启用。系统没有任何梯度下降，因此不会从数据中发现模式，只会执行设计者预设的规则。

**L3 · 感知层是特征向量而非真实信号。** 图像输入是 8 维合成特征（RGB + 圆度 + 边缘密度 + 3 维风格），语音输入是 8 维合成特征，**不是像素，也不是波形**。系统跳过了整个「从原始信号到语义」的前端感知难题，这是本项目最大的能力缺口。

**L4 · 推理能力极浅。** 规则库仅 11 条种子规则，前向链接深度 ≤3，第三通道是模板兜底。所谓「推理」本质上是模式匹配加优先级仲裁，不具备组合泛化、反事实推理或因果推断能力。

**L5 · M1/M2 嵌入空间未统一（架构债）。** M1 的 `_shared.py` 复刻的是 M2 早期桩版本的哈希词袋嵌入，而 M2 已升级为概念锚定嵌入。结果是注意力 α 通道（余弦）实际是跨空间比较的弱信号，β 通道（token Jaccard）与规则通道仍在语义上有效。系统能跑通是因为三通道仲裁稀释了 α 的噪声，但这是需要偿还的债，不是设计优势。

**L6 · 演示汇总逻辑不严谨。** `demo/run_demo.py` 中 `scenes_ok = [True, True, True]` 为硬编码，场景成功判定实际依赖各场景内部 `_check` 的 PASS/FAIL 累计。全绿结论正确，但汇总代码形式上是占位实现，若新增场景而忘记更新该列表，会给出错误的汇总判定。

**L7 · 冗余别名实体。** 存在三对命名别名文件（`reasoning.py`/`reasoner.py`、`aligner.py`/`align.py`、`image_encoder.py`/`vision_encoder.py`），源于任务书与设计文档命名口径不一致。功能等价，但构成三处双份维护成本。

**L8 · 长时程行为未验证。** 记忆系统设计了 1000 条上限、遗忘曲线衰减与归档策略，但所有测试均为短时程（最多千条 / 数轮对话）。长期运行下的记忆膨胀、衰减收敛性、巩固质量退化均未实测。

## 7. 演进路线

### 近期（P0，偿还架构债）

1. **统一共享嵌入服务**——将 M2 的概念锚定嵌入提升为全系统共享服务，M1 注意力 α 通道接入同一空间，消除 L5 的跨空间比较问题。这是当前投入产出比最高的一项。
2. **收敛三对别名文件**——确认无外部依赖后合并为单一命名，或在 `__init__.py` 中显式声明别名并保持单一实现源，落实「如无必要，勿增实体」。
3. **修正演示汇总逻辑**——以各场景返回值驱动汇总，取代硬编码列表（L6）。
4. **回写 README 状态**——建立「代码合入即回写进度」的机制，避免文档与实现漂移。

### 中期（P1，能力增强）

5. **真实信号前端**——接入真实图像的像素级编码与真实音频的波形特征提取，替换 8 维合成特征，正面应对 L3。
6. **可学习对齐**——启用 T2 岭回归通道并引入真实训练循环，让跨模态映射由数据驱动而非纯结构保证，应对 L2。
7. **规则库自动归纳**——从记忆中的高频情景自动抽取候选规则，经人工或置信度阈值审核后入库，突破 11 条静态规则的上限（L4）。
8. **长时程记忆压测**——构造万条级、跨百轮的记忆负载，实测衰减与巩固的稳定性（L8）。

### 长期（P2，架构演进）

9. **LLM 后端接入**——`docs/architecture.md` 已预留演进位：将 M1 的推理通道替换为 LLM 驱动，四层架构与 I1–I6 契约不变。这是本架构最重要的设计价值——重型实现可替换而架构不动。
10. **服务化与并发**——`dispatch` 签名不变的前提下增加 HTTP POST 适配层，引入会话隔离与并发控制。
11. **开放域评测基准**——引入真实多模态基准数据集，在开放域上重新度量，以检验本系统在封闭世界的指标到底有多少能迁移。

## 8. 结论

AGI-Core 在纯本地 CPU、零外部依赖的约束下，完成了从架构设计到系统集成的完整研发闭环，六条验收标准全部达成，全部指标经独立复跑验证。

这套系统的真正价值不在于指标有多高——在封闭合成数据上取得 1.0 并不值得夸耀——而在于它验证了三件事：**契约先行能让四个模块并行开发后一次性集成成功**；**降级内建能让无 GPU / 无外网的极端环境不阻塞任何流程**；**分层架构能让未来的重型实现替换局限在单个模块内**。

局限同样真实：它是封闭世界里的规则系统，不是开放域的认知智能。但作为一条可演进的基线，它的骨架是干净的，债是清楚的，下一步往哪走是明确的。
